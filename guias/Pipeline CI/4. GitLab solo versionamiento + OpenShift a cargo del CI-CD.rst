================================================================================
Guia Definitiva: Resolucion de Pipeline Inline con Pipelines as Code (PaC)
y Git-Clone en OpenShift Local (CRC) y GitLab Local
================================================================================

Resumen del Problema
--------------------
Al implementar un pipeline inline utilizando **Pipelines as Code (PaC)** en OpenShift Local (CRC) conectándose a un servidor **GitLab CE local** (`http://192.168.123.121`), se presentaron múltiples bloqueos consecutivos:
1. **Errores de sintaxis y compatibilidad:** Uso inicial de versiones obsoletas de la API de Tekton en lugar de `tekton.dev/v1`.
2. **Falla de autenticación en scripts personalizados (`taskSpec`):** Los intentos de clonar mediante scripts manuales de Bash utilizando Alpine Git fallaban porque el secreto generado automáticamente por PaC (`pac-gitauth-...`) almacena archivos estructurados (`.git-credentials` y `.gitconfig`) y no llaves sueltas de tipo `userid`/`password`.
3. **Error `CouldntGetTask`:** Al intentar referenciar tareas remotas con `taskRef` sin una definición local ni el resolvedor adecuado, el controlador de PaC no lograba encontrar ni inyectar la tarea.

La Solucion Definitiva y Patron Arquitectonico
---------------------------------------------
Para lograr una solucion robusta, limpia y nativa sin recurrir a scripts de Bash frágiles ni lógica manual de credenciales, se aplico el siguiente patron validado:

1. **Anotacion de Resolucion Remota:** Se utiliza la anotacion de metadatos `pipelinesascode.tekton.dev/task: "git-clone"` para indicarle al controlador que obtenga y cachee automaticamente la tarea oficial del catalogo.
2. **Workspace `basic-auth` Nativo:** Se enlaza el secreto gestionado por PaC (`{{ git_auth_secret }}`) a un workspace llamado `basic-auth`. La tarea oficial `git-clone` detecta internamente este workspace y configura de forma transparente las credenciales de Git a partir del archivo `.git-credentials`.
3. **Estructura YAML Limpia (API v1):** Declaracion de parametros globales, creacion dinamica de volumenes (`PersistentVolumeClaimTemplate`) para el espacio compartido de trabajo y referencia limpia a la tarea oficial.

---

El Manifiesto YAML Final y Funcional (`.tekton/pipelinerun.yaml`)
-----------------------------------------------------------------

.. code-block:: yaml

    apiVersion: tekton.dev/v1
    kind: PipelineRun
    metadata:
      name: my-app-simple-inline-pipeline
      annotations:
        pipelinesascode.tekton.dev/on-event: "[push]"
        pipelinesascode.tekton.dev/on-target-branch: "[develop]"
        pipelinesascode.tekton.dev/max-keep-runs: "3"
        pipelinesascode.tekton.dev/task: "git-clone"
    spec:
      params:
        - name: repo_url
          value: "{{ repo_url }}"
        - name: revision
          value: "{{ revision }}"
      workspaces:
        - name: shared-workspace
          volumeClaimTemplate:
            spec:
              accessModes:
                - ReadWriteOnce
              resources:
                requests:
                  storage: 1Gi
        - name: basic-auth
          secret:
            secretName: "{{ git_auth_secret }}"
      pipelineSpec:
        params:
          - name: repo_url
          - name: revision
        workspaces:
          - name: shared-workspace
          - name: basic-auth
        tasks:
          - name: git-clone
            taskRef:
              name: git-clone
            params:
              - name: url
                value: "$(params.repo_url)"
              - name: revision
                value: "$(params.revision)"
              - name: sslVerify
                value: "false"
            workspaces:
              - name: output
                workspace: shared-workspace
              - name: basic-auth
                workspace: basic-auth

---

Pasos de Ejecucion y Verificacion en Terminal
---------------------------------------------

1. **Editar el archivo de configuracion localmente:**

   .. code-block:: bash

       cd ~/my-app-simple
       nano .tekton/pipelinerun.yaml

2. **Validar la resolucion del pipeline localmente (Opcional):**

   .. code-block:: bash

       tkn pac resolve -f .tekton/pipelinerun.yaml

3. **Hacer commit y push de los cambios hacia la rama `develop` en GitLab:**

   .. code-block:: bash

       git add .tekton/pipelinerun.yaml
       git commit -m "fix: final native git-clone task integration with basic-auth"
       git push origin develop

4. **Monitorear la ejecucion exitosa en tiempo real en OpenShift:**

   .. code-block:: bash

       oc get pipelineruns -n my-app-dev -w
