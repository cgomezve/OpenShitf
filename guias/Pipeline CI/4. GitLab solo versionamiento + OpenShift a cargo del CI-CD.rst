Introducción
============

Este manual recopila de principio a fin todo el diseño arquitectónico, los requisitos previos de red, la configuración del operador de Pipelines as Code (PaC), la resolución de bloqueos de seguridad (SCC), los ajustes de almacenamiento en volúmenes efímeros y la estabilización del pipeline de compilación y despliegue continuo en OpenShift.

Paso 0: Habilitar Webhooks locales en GitLab (Requisito crítico)
================================================================

Por defecto, GitLab bloquea las peticiones de Webhooks hacia direcciones IP privadas o dominios locales (como `apps-crc.testing`) por políticas de seguridad (SSRF). 

1. Inicia sesión en GitLab con una cuenta de Administrador.
2. Ve a **Admin Area** (icono de llave inglesa) → **Settings** → **Network**.
3. Expande la sección **Outbound requests**.
4. Marca la casilla **Allow requests to the local network from webhooks and integrations**.
5. Haz clic en **Save changes**.

Paso 1: Desactivar el CI/CD nativo de GitLab
============================================

Para evitar ejecuciones duplicadas o conflictos de compilación en GitLab:

1. Entra a tu proyecto en GitLab.
2. En el menú lateral ve a **Settings** → **General**.
3. Expande **Visibility, project features, permissions**.
4. En la sección **Repository**, desactiva el interruptor **CI/CD**.
5. Haz clic en **Save changes**.

Paso 2: Instalar y habilitar OpenShift Pipelines (Tekton) y PaC
===============================================================

Como administrador del clúster (`kubeadmin`), instala el operador oficial:

1. Crear la suscripción para el operador:

   .. code-block:: bash

      cat <<EOF | oc apply -f -
      apiVersion: operators.coreos.com/v1alpha1
      kind: Subscription
      metadata:
        name: openshift-pipelines-operator-rh
        namespace: openshift-operators
      spec:
        channel: latest
        installPlanApproval: Automatic
        name: openshift-pipelines-operator-rh
        source: redhat-operators
        sourceNamespace: openshift-marketplace
      EOF

2. Asegurar la activación del controlador Pipelines as Code en `TektonConfig`:

   .. code-block:: bash

      oc patch tektonconfig config --type=merge -p='{"spec":{"platforms":{"openshift":{"pipelinesAsCode":{"enable":true}}}}}'

3. Verificar que los componentes levanten correctamente:

   .. code-block:: bash

      oc get pods -n openshift-pipelines

Paso 3: Crear el Namespace y configurar ServiceAccounts y Permisos SCC
====================================================================

Para permitir que las tareas del pipeline (especialmente Buildah y las operaciones `oc`) se ejecuten con los privilegios adecuados en OpenShift:

1. Crear el proyecto (namespace):

   .. code-block:: bash

      oc new-project my-app-dev
      oc project my-app-dev

2. Otorgar los privilegios de Security Context Constraints (SCC) `privileged` y `anyuid` al ServiceAccount `pipeline`:

   .. code-block:: bash

      oc adm policy add-scc-to-user privileged system:serviceaccount:my-app-dev:pipeline
      oc adm policy add-scc-to-user anyuid system:serviceaccount:my-app-dev:pipeline
      oc policy add-role-to-user edit -z pipeline -n my-app-dev

Paso 4: Obtener la URL del controlador de PaC
=============================================

Obtén la ruta pública de OpenShift hacia donde GitLab enviará los webhooks:

.. code-block:: bash

   echo https://$(oc get route -n openshift-pipelines pipelines-as-code-controller -o jsonpath='{.spec.host}')

Paso 5: Configurar el Repository CR en OpenShift y Webhook en GitLab
=====================================================================

Crea el recurso `Repository` apuntando a tu instancia HTTP de GitLab y configura el secreto con el token de acceso personal (`api` y `admin:repo_hook`). 

*(Asegúrate de configurar el Webhook en GitLab apuntando a la ruta del controlador de PaC y desmarcar la verificación SSL si utilizas certificados autofirmados en CRC).*

Paso 6: Estructura del Repositorio Local (`~/my-app-simple`)
===========================================================

El proyecto mantiene la siguiente distribución de archivos:

.. code-block:: text

   my-app-simple/
   ├── .tekton/
   │   └── pipelinerun.yaml      # Definición del PipelineRun con PaC
   ├── kubernetes/
   │   └── deployment.yaml       # Manifiestos de Deployment y Service para my-app-dev
   ├── contador.txt              # Archivo de control para pruebas de commits
   └── Dockerfile                # Imagen base (nginx:alpine)

Paso 7: Manifiesto Consolidado Final `.tekton/pipelinerun.yaml`
==============================================================

Este manifiesto integra todas las correcciones necesarias:
* Uso de workspace efímero (`emptyDir: {}`) para evitar bloqueos de permisos de escritura.
* Parámetro `subdirectory: ""` en `git-clone` para asegurar que los archivos queden listos en la raíz del workspace compartido (`/workspace/source/`).
* Configuración estricta de `CONTEXT: "."` y `DOCKERFILE: "Dockerfile"` para que la tarea `buildah` localice el archivo sin errores.
* Despliegue automático y validación de rollout en el namespace `my-app-dev`.

.. code-block:: yaml

   apiVersion: tekton.dev/v1
   kind: PipelineRun
   metadata:
     name: my-app-simple-full-pipeline
     annotations:
       pipelinesascode.tekton.dev/on-event: "[push]"
       pipelinesascode.tekton.dev/on-target-branch: "[develop]"
       pipelinesascode.tekton.dev/max-keep-runs: "3"
       pipelinesascode.tekton.dev/task: "[git-clone, buildah]"
   spec:
     params:
       - name: repo_url
         value: "{{ repo_url }}"
       - name: revision
         value: "{{ revision }}"
     workspaces:
       - name: shared-workspace
         emptyDir: {}
       - name: basic-auth
         secret:
           secretName: "{{ git_auth_secret }}"
     pipelineSpec:
       params:
         - name: repo_url
         - name: revision
       workspaces:
         - name: shared-workspace
         - name: basic-auth
       tasks:
         - name: git-clone
           taskRef:
             name: git-clone
           params:
             - name: url
               value: "$(params.repo_url)"
             - name: revision
               value: "$(params.revision)"
             - name: sslVerify
               value: "false"
             - name: subdirectory
               value: ""
           workspaces:
             - name: output
               workspace: shared-workspace
             - name: basic-auth
               workspace: basic-auth

         - name: build-image
           taskRef:
             name: buildah
           runAfter:
             - git-clone
           params:
             - name: IMAGE
               value: "image-registry.openshift-image-registry.svc:5000/my-app-dev/my-app-simple:$(params.revision)"
             - name: STORAGE_DRIVER
               value: "vfs"
             - name: TLSVERIFY
               value: "false"
             - name: CONTEXT
               value: "."
             - name: DOCKERFILE
               value: "Dockerfile"
           workspaces:
             - name: source
               workspace: shared-workspace

         - name: deploy-app
           runAfter:
             - build-image
           workspaces:
             - name: source
               workspace: shared-workspace
           taskSpec:
             workspaces:
               - name: source
             steps:
               - name: apply-and-verify
                 image: quay.io/openshift/origin-cli:latest
                 script: |
                   #!/usr/bin/env bash
                   set -e
                   cd $(workspaces.source.path)
                   oc apply -f kubernetes/deployment.yaml -n my-app-dev
                   oc set image deployment/my-app-simple my-app-simple=image-registry.openshift-image-registry.svc:5000/my-app-dev/my-app-simple:$(params.revision) -n my-app-dev
                   oc rollout status deployment/my-app-simple -n my-app-dev --timeout=300s

Paso 8: Operación, Monitoreo y Comandos Útiles
=============================================

* **Sincronización y Envío a GitLab:**

  .. code-block:: bash

     cd ~/my-app-simple
     git add .
     git commit -m "feat: complete pipeline setup and configuration"
     git push origin develop

* **Monitoreo de PipelineRuns en OpenShift:**

  .. code-block:: bash

     oc get pipelineruns -n my-app-dev -w

* **Inspección de Pods y Logs ante incidencias:**

  .. code-block:: bash

     oc get pods -n my-app-dev
     oc logs -n my-app-dev <nombre-del-pod> --tail=100
