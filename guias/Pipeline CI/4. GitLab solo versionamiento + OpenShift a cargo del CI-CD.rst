=============================================================================
Migración CI/CD de GitLab HTTP a OpenShift con Pipelines as Code (Tekton)
=============================================================================

:Autor: Carlos Gómez
:Entorno: Red Hat OpenShift Local (CRC) / GitLab CE Local (HTTP sin SSL)
:Proyecto: ``my-app-dev``
:Repositorio: ``http://192.168.123.121/soporte-web/my-app-simple.git``

.. contents:: Contenido
   :depth: 2

1. Requisitos Previos en GitLab (Entorno HTTP Local)
===================================================

Debido a que la instancia de GitLab opera en una red privada mediante HTTP sin certificados SSL, es obligatorio autorizar las peticiones salientes hacia redes locales antes de configurar los webhooks.

1.1. Habilitar Webhooks hacia Redes Locales
-------------------------------------------

1. Ingresar a GitLab con una cuenta con privilegios de administrador.
2. Navegar a **Admin Area > Settings > Network**.
3. Expandir la sección **Outbound requests**.
4. Marcar únicamente la casilla:
   **Allow requests to the local network from webhooks and integrations**
5. Hacer clic en **Save changes**.

1.2. Generar Personal Access Token (PAT)
----------------------------------------

1. Ir a **User Settings > Access Tokens**.
2. Crear un token con los alcances (scopes): ``api``, ``read_repository`` y ``write_repository``.
3. Guardar el valor del token generado para registrarlo posteriormente en OpenShift.

2. Preparación del Clúster OpenShift (CRC)
==========================================

2.1. Verificar el Operador OpenShift Pipelines y PaC
----------------------------------------------------

Confirmar que el componente Pipelines as Code esté habilitado en la configuración de Tekton y que los pods estén en estado ``Running``:

.. code-block:: bash

   oc patch tektonconfig config --type=merge -p='{"spec":{"platforms":{"openshift":{"pipelinesAsCode":{"enable":true}}}}}'
   oc get pods -n openshift-pipelines

2.2. Obtener la URL del Webhook del Controlador PaC
---------------------------------------------------

Extraer la ruta pública expuesta por OpenShift para recibir los eventos desde GitLab:

.. code-block:: bash

   oc get route -n openshift-pipelines pipelines-as-code-controller

La URL oficial para el Webhook será:

.. code-block:: text

   https://pipelines-as-code-controller-openshift-pipelines.apps-crc.testing

3. Configuración del Proyecto y Permisos RBAC
=============================================

3.1. Crear el Namespace de Trabajo
----------------------------------

.. code-block:: bash

   oc new-project my-app-dev
   oc project my-app-dev

3.2. Configurar ServiceAccounts y Roles
---------------------------------------

Crear el ``ServiceAccount`` dedicado al despliegue y asignar permisos de edición y lectura tanto al deployer como al ``ServiceAccount`` predeterminado de Tekton (``pipeline``):

.. code-block:: bash

   # Crear el ServiceAccount dedicado para GitLab/Deployer
   oc create sa gitlab-deployer-sa

   # Dar permisos de edición al ServiceAccount deployer
   oc policy add-role-to-user edit -z gitlab-deployer-sa -n my-app-dev

   # Dar permisos de edición al ServiceAccount predeterminado de Tekton ('pipeline')
   oc policy add-role-to-user edit -z pipeline -n my-app-dev

   # Dar permisos de lectura al ServiceAccount predeterminado de Tekton ('pipeline')
   oc policy add-role-to-user view -z pipeline -n my-app-dev

4. Instalación de CLI Tekton (``tkn``) en Estación Debian
=========================================================

Instalar el binario oficial de ``tkn`` en una ruta del sistema (``/usr/local/bin/``) fuera de los directorios de repositorios Git para evitar contaminar el código fuente:

.. code-block:: bash

   # Descargar en directorio temporal
   cd /tmp
   curl -LO https://github.com/tektoncd/cli/releases/download/v0.38.0/tkn_0.38.0_Linux_x86_64.tar.gz

   # Extraer directamente en /usr/local/bin
   sudo tar xvzf tkn_0.38.0_Linux_x86_64.tar.gz -C /usr/local/bin/ tkn

   # Limpiar el archivo comprimido
   rm /tmp/tkn_0.38.0_Linux_x86_64.tar.gz

   # Verificar instalación
   tkn version

.. note::
   Si el binario ``tkn`` fue descargado por error dentro de un repositorio clonado, moverlo con ``sudo mv tkn /usr/local/bin/`` y eliminar el ``.tar.gz`` antes de ejecutar ``git add``.

5. Preparación del Repositorio y Plantilla ``.tekton/``
=======================================================

5.1. Clonar el Repositorio y Cambiar a la Rama ``develop``
----------------------------------------------------------

.. code-block:: bash

   git clone http://192.168.123.121/soporte-web/my-app-simple.git
   cd my-app-simple
   git checkout -b develop
   mkdir -p .tekton

5.2. Crear el Manifiesto ``.tekton/pipelinerun.yaml``
-----------------------------------------------------

Crear el archivo ``.tekton/pipelinerun.yaml``. Este manifiesto viaja dentro del código fuente del repositorio y puede entregarse como plantilla estándar a los equipos de desarrollo. Se dispara automáticamente al realizar ``push`` sobre la rama ``develop``:

.. code-block:: yaml

   apiVersion: tekton.dev/v1
   kind: PipelineRun
   metadata:
     name: my-app-simple-dev-pipeline
     annotations:
       pipelinesascode.tekton.dev/on-event: "[push]"
       pipelinesascode.tekton.dev/on-target-branch: "[develop]"
       pipelinesascode.tekton.dev/task: "[git-clone, buildah]"
       pipelinesascode.tekton.dev/max-keep-runs: "3"
   spec:
     params:
       - name: repo_url
         value: "{{ repo_url }}"
       - name: revision
         value: "{{ revision }}"
       - name: image_name
         value: "image-registry.openshift-image-registry.svc:5000/my-app-dev/my-app-simple:{{ revision }}"
     workspaces:
       - name: source
         volumeClaimTemplate:
           spec:
             accessModes:
               - ReadWriteOnce
             resources:
               requests:
                 storage: 1Gi
     pipelineSpec:
       params:
         - name: repo_url
         - name: revision
         - name: image_name
       workspaces:
         - name: source
       tasks:
         - name: fetch-repository
           taskRef:
             name: git-clone
             kind: ClusterTask
           workspaces:
             - name: output
               workspace: source
           params:
             - name: url
               value: $(params.repo_url)
             - name: revision
               value: $(params.revision)
             - name: sslVerify
               value: "false"
         - name: build-image
           runAfter:
             - fetch-repository
           taskRef:
             name: buildah
             kind: ClusterTask
           workspaces:
             - name: source
               workspace: source
           params:
             - name: IMAGE
               value: $(params.image_name)
             - name: TLSVERIFY
               value: "false"

5.3. Subir la Plantilla al Repositorio Remoto
---------------------------------------------

.. code-block:: bash

   git add .tekton/pipelinerun.yaml
   git commit -m "feat: add tekton pipelines-as-code pipelinerun for develop branch"
   git push origin develop

6. Vinculación del Repositorio y Webhook
========================================

6.1. Registrar el Recurso ``Repository`` en OpenShift
-----------------------------------------------------

Crear el Secret con el Personal Access Token de GitLab y una clave aleatoria para validar la firma del Webhook:

.. code-block:: bash

   oc create secret generic gitlab-webhook-secret \
     --from-literal=provider.token="<TU_GITLAB_PAT>" \
     --from-literal=webhook.secret="<CLAVE_SECRETA_WEBHOOK>" \
     -n my-app-dev

Crear y aplicar el manifiesto ``Repository`` apuntando explícitamente a la URL ``http://``:

.. code-block:: yaml

   apiVersion: "pipelinesascode.tekton.dev/v1alpha1"
   kind: Repository
   metadata:
     name: my-app-simple
     namespace: my-app-dev
   spec:
     url: "http://192.168.123.121/soporte-web/my-app-simple.git"
     git_provider:
       type: gitlab
       url: "http://192.168.123.121"
       secret:
         name: "gitlab-webhook-secret"
         key: "provider.token"
       webhook_secret:
         name: "gitlab-webhook-secret"
         key: "webhook.secret"

Aplicar el recurso en el clúster:

.. code-block:: bash

   oc apply -f repository.yaml

6.2. Configurar el Webhook en el Proyecto de GitLab
---------------------------------------------------

1. En GitLab, ir al proyecto **soporte-web/my-app-simple > Settings > Webhooks**.
2. Completar los campos:

   * **URL:** ``https://pipelines-as-code-controller-openshift-pipelines.apps-crc.testing``
   * **Secret token:** El mismo valor definido en ``webhook.secret``.
   * **Trigger:** Marcar **Push events** (opcionalmente filtrar por la rama ``develop``) y **Merge request events**.
   * **SSL verification:** Desmarcar **Enable SSL verification** (debido a los certificados autofirmados de CRC).

3. Guardar con **Add webhook** y ejecutar **Test > Push events** para validar respuesta HTTP ``202 Accepted``.

7. Verificación de Ejecución del Pipeline
=========================================

Comprobar desde la terminal que Pipelines as Code haya recibido el evento y disparado el ``PipelineRun``:

.. code-block:: bash

   # Listar ejecuciones en el namespace
   tkn pipelinerun list -n my-app-dev

   # Seguir los logs en tiempo real de la última ejecución
   tkn pipelinerun logs --last -f -n my-app-dev
