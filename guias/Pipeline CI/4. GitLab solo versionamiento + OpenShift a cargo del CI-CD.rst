================================================================================
Guía de Implementación y Troubleshooting: Pipeline CI/CD con OpenShift Local (CRC), Pipelines as Code (PaC) y GitLab CE
================================================================================

1. Arquitectura y Entorno de Laboratorio
--------------------------------------------------------------------------------
El presente documento consolida la configuración, diagnóstico y evolución técnica de un flujo de integración y despliegue continuo (CI/CD) de punta a punta entre **GitLab CE Local** y **Red Hat OpenShift Local (CRC)**.

* **Servidor GitLab CE Local:** ``http://192.168.123.121`` (rama objetivo: ``develop``).
* **Clúster Destino:** OpenShift Local (CRC) — Namespace ``my-app-dev``.
* **Motor CI/CD:** OpenShift Pipelines (Tekton) con Pipelines as Code (PaC).
* **Estación de Desarrollo:** Debian Linux (``~/my-app-simple``).

**Estructura del Repositorio (``~/my-app-simple``):**

.. code-block:: text

   my-app-simple/
   ├── .tekton/
   │   └── pipelinerun.yaml      # Definición del PipelineRun y disparadores PaC
   ├── kubernetes/
   │   └── deployment.yaml       # Manifiesto de Deployment y Service en my-app-dev
   ├── contador.txt              # Archivo de control para pruebas de commits
   └── Dockerfile                # Imagen base (nginx:alpine)


2. Configuración de Seguridad y Permisos (SCC)
--------------------------------------------------------------------------------
Para permitir que los contenedores de construcción (``buildah``) y despliegue ejecuten operaciones privilegiadas y montajes dentro del clúster sin ser bloqueados por las políticas de seguridad por defecto de OpenShift, se asignaron los Security Context Constraints (SCC) ``privileged`` y ``anyuid`` al ServiceAccount ``pipeline``:

.. code-block:: bash

   oc adm policy add-scc-to-user privileged -z pipeline -n my-app-dev
   oc adm policy add-scc-to-user anyuid -z pipeline -n my-app-dev


3. Bitácora de Diagnóstico y Troubleshooting Progresivo
--------------------------------------------------------------------------------
Durante las pruebas de ejecución automatizada mediante webhooks desde GitLab, se identificaron y resolvieron secuencialmente los siguientes bloqueos técnicos:

3.1. Bloqueo de Permisos de Escritura en el Workspace Compartido
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
* **Síntoma:** Falla en la inicialización y clonado al intentar escribir sobre un PersistentVolumeClaim (PVC) sin permisos adecuados o con conflictos de aprovisionamiento dinámico.
* **Solución:** Se migró el workspace principal ``shared-workspace`` dentro de ``.tekton/pipelinerun.yaml`` hacia un volumen efímero ``emptyDir: {}``, garantizando lectura y escritura inmediata entre todas las tareas del PipelineRun.

3.2. Archivos de Manifiestos sin Seguimiento en Git (Untracked)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
* **Síntoma:** Al ejecutar ``git add .tekton/pipelinerun.yaml contador.txt Dockerfile``, Git indicaba que no había cambios nuevos mientras la carpeta ``kubernetes/`` permanecía sin seguimiento (``untracked``), impidiendo que la fase de despliegue encontrara ``kubernetes/deployment.yaml``.
* **Solución:** Inclusión completa del directorio de manifiestos en el control de versiones:

.. code-block:: bash

   cd ~/my-app-simple
   git add .
   git commit -m "feat: include kubernetes manifests and pipeline configuration for deployment"
   git push origin develop

3.3. Error de Esquema al Consultar Logs con ``oc logs taskrun/...``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
* **Síntoma:** Al intentar leer registros directamente sobre el recurso Tekton, el cliente CLI arrojaba:
  ``error: no kind "TaskRun" is registered for version "tekton.dev/v1" in scheme "k8s.io/kubectl/pkg/scheme/scheme.go:28"``
* **Solución:** Inspeccionar directamente los Pods asociados a cada ejecución en lugar del objeto ``TaskRun``:

.. code-block:: bash

   oc get taskruns -n my-app-dev | grep <id-ejecucion>
   oc get pods -n my-app-dev
   oc logs -n my-app-dev <nombre-del-pod> --tail=100

3.4. Fallos en la Tarea ``build-image`` (Buildah) por Ruta del Dockerfile
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
* **Historial de Ejecuciones Analizadas:** ``tlvlr``, ``fzrk4``, ``vlm5d``, ``cmd4l`` y ``h6zh4``.
* **Comportamiento Observado:** La tarea ``git-clone`` finalizaba consistentemente en estado ``Succeeded`` (``True``), pero ``build-image`` fallaba en segundos (``StepFailed``) arrojando en el contenedor ``step-build-and-push``:
  ``Error: stat /workspace/source/Dockerfile: no such file or directory``
* **Ajustes Aplicados en Iteraciones:**
  1. Se configuró ``subdirectory: ""`` en la tarea ``git-clone`` para forzar la descarga del repositorio en la raíz del workspace compartido (``/workspace/source/``) en lugar de crear una subcarpeta con el nombre del proyecto.
  2. Se definieron explícitamente los parámetros de ``buildah``: ``CONTEXT: "."`` y se probó la transición de ``DOCKERFILE: "./Dockerfile"`` a ``DOCKERFILE: "Dockerfile"``.


4. Definición Completa de ``.tekton/pipelinerun.yaml``
--------------------------------------------------------------------------------
A continuación se presenta el manifiesto consolidado con todas las etapas (``git-clone``, ``build-image`` y ``deploy-app``) y parámetros ajustados hasta la última revisión:

.. code-block:: yaml

   apiVersion: tekton.dev/v1
   kind: PipelineRun
   metadata:
     name: my-app-simple-full-pipeline
     annotations:
       pipelinesascode.tekton.dev/on-event: "[push]"
       pipelinesascode.tekton.dev/on-target-branch: "[develop]"
       pipelinesascode.tekton.dev/max-keep-runs: "3"
       pipelinesascode.tekton.dev/task: "[git-clone, buildah]"
   spec:
     params:
       - name: repo_url
         value: "{{ repo_url }}"
       - name: revision
         value: "{{ revision }}"
     workspaces:
       - name: shared-workspace
         emptyDir: {}
       - name: basic-auth
         secret:
           secretName: "{{ git_auth_secret }}"
     pipelineSpec:
       params:
         - name: repo_url
         - name: revision
       workspaces:
         - name: shared-workspace
         - name: basic-auth
       tasks:
         - name: git-clone
           taskRef:
             name: git-clone
           params:
             - name: url
               value: "$(params.repo_url)"
             - name: revision
               value: "$(params.revision)"
             - name: sslVerify
               value: "false"
             - name: subdirectory
               value: ""
           workspaces:
             - name: output
               workspace: shared-workspace
             - name: basic-auth
               workspace: basic-auth

         - name: build-image
           taskRef:
             name: buildah
           runAfter:
             - git-clone
           params:
             - name: IMAGE
               value: "image-registry.openshift-image-registry.svc:5000/my-app-dev/my-app-simple:$(params.revision)"
             - name: STORAGE_DRIVER
               value: "vfs"
             - name: TLSVERIFY
               value: "false"
             - name: CONTEXT
               value: "."
             - name: DOCKERFILE
               value: "Dockerfile"
           workspaces:
             - name: source
               workspace: shared-workspace

         - name: deploy-app
           runAfter:
             - build-image
           workspaces:
             - name: source
               workspace: shared-workspace
           taskSpec:
             workspaces:
               - name: source
             steps:
               - name: apply-and-verify
                 image: quay.io/openshift/origin-cli:latest
                 script: |
                   #!/usr/bin/env bash
                   set -e
                   cd $(workspaces.source.path)
                   oc apply -f kubernetes/deployment.yaml -n my-app-dev
                   oc set image deployment/my-app-simple my-app-simple=image-registry.openshift-image-registry.svc:5000/my-app-dev/my-app-simple:$(params.revision) -n my-app-dev
                   oc rollout status deployment/my-app-simple -n my-app-dev --timeout=300s


5. Comandos de Operación, Monitoreo y Próximo Paso de Depuración
--------------------------------------------------------------------------------

**5.1. Flujo de Actualización desde Debian:**

.. code-block:: bash

   cd ~/my-app-simple
   git add .
   git commit -m "fix: update pipeline configuration"
   git push origin develop

**5.2. Monitoreo en Tiempo Real en OpenShift:**

.. code-block:: bash

   oc get pipelineruns -n my-app-dev -w

**5.3. Paso Pendiente para Verificar la Ruta Exacta en el Workspace:**
Dado que la última ejecución volvió a fallar en ``build-image``, el siguiente paso de diagnóstico consiste en consultar el log del pod más reciente o añadir un paso temporal de inspección (``ls -la /workspace/source``) antes de ``buildah`` para confirmar exactamente en qué directorio depositó ``git-clone`` los archivos del repositorio:

.. code-block:: bash

   oc get pods -n my-app-dev --sort-by=.metadata.creationTimestamp
   oc logs -n my-app-dev <ultimo-pod-build-image> --tail=100
