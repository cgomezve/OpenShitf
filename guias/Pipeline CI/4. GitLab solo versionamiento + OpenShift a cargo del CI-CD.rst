================================================================================
Documentación de Implementación y Troubleshooting: Pipeline CI/CD con OpenShift Local, Pipelines as Code (PaC) y GitLab
================================================================================

Resumen del Proyecto
--------------------------------------------------------------------------------
Implementación exitosa de un pipeline de CI/CD de punta a punta utilizando Pipelines as Code (PaC) en OpenShift Local (CRC) y GitLab CE Local, resolviendo progresivamente errores de permisos, volúmenes de trabajo y rutas de compilación para automatizar el despliegue de aplicaciones en el namespace ``my-app-dev``.


1. Configuración Inicial y Privilegios SCC
--------------------------------------------------------------------------------
Para permitir que las tareas del pipeline (especialmente Buildah y las operaciones de despliegue) se ejecuten correctamente sin bloqueos de seguridad en OpenShift, se otorgaron los privilegios de Security Context Constraints (SCC) ``privileged`` y ``anyuid`` al ServiceAccount ``pipeline``:

.. code-block:: bash

   oc adm policy add-scc-to-user privileged system:serviceaccount:my-app-dev:pipeline
   oc adm policy add-scc-to-user anyuid system:serviceaccount:my-app-dev:pipeline


2. Resolución de Bloqueos de Permisos de Escritura
--------------------------------------------------------------------------------
Se solucionaron los errores de permisos de escritura en el espacio de trabajo compartido migrando el workspace principal en el PipelineRun a un volumen temporal ``emptyDir``:

.. code-block:: yaml

   workspaces:
     - name: shared-workspace
       emptyDir: {}


3. Estructura de Archivos del Repositorio
--------------------------------------------------------------------------------
El repositorio local (``~/my-app-simple``) quedó estructurado de la siguiente forma para soportar tanto la compilación como los manifiestos de Kubernetes:

* ``Dockerfile``: Imagen base (ej. ``nginx:alpine``).
* ``contador.txt``: Archivo de control y pruebas de cambios.
* ``kubernetes/deployment.yaml``: Manifiestos de despliegue y servicio para ``my-app-dev``.
* ``.tekton/pipelinerun.yaml``: Configuración de Pipelines as Code para disparar ejecuciones automáticas en cada ``git push`` hacia la rama ``develop``.


4. Evolución y Solución del PipelineRun
--------------------------------------------------------------------------------
Tras resolver progresivamente los fallos de clonado (configurando ``subdirectory: ""`` para volcar los archivos directamente en la raíz del workspace compartido) y ajustar los parámetros de la tarea ``buildah`` (``CONTEXT: "."`` y ``DOCKERFILE: "Dockerfile"``), la estructura final del archivo `.tekton/pipelinerun.yaml` quedó consolidada de la siguiente manera:

.. code-block:: yaml

   apiVersion: tekton.dev/v1
   kind: PipelineRun
   metadata:
     name: my-app-simple-full-pipeline
     annotations:
       pipelinesascode.tekton.dev/on-event: "[push]"
       pipelinesascode.tekton.dev/on-target-branch: "[develop]"
       pipelinesascode.tekton.dev/max-keep-runs: "3"
       pipelinesascode.tekton.dev/task: "[git-clone, buildah]"
   spec:
     params:
       - name: repo_url
         value: "{{ repo_url }}"
       - name: revision
         value: "{{ revision }}"
     workspaces:
       - name: shared-workspace
         emptyDir: {}
       - name: basic-auth
         secret:
           secretName: "{{ git_auth_secret }}"
     pipelineSpec:
       params:
         - name: repo_url
         - name: revision
       workspaces:
         - name: shared-workspace
         - name: basic-auth
       tasks:
         - name: git-clone
           taskRef:
             name: git-clone
           params:
             - name: url
               value: "$(params.repo_url)"
             - name: revision
               value: "$(params.revision)"
             - name: sslVerify
               value: "false"
             - name: subdirectory
               value: ""
           workspaces:
             - name: output
               workspace: shared-workspace
             - name: basic-auth
               workspace: basic-auth

         - name: build-image
           taskRef:
             name: buildah
           runAfter:
             - git-clone
           params:
             - name: IMAGE
               value: "image-registry.openshift-image-registry.svc:5000/my-app-dev/my-app-simple:$(params.revision)"
             - name: STORAGE_DRIVER
               value: "vfs"
             - name: TLSVERIFY
               value: "false"
             - name: CONTEXT
               value: "."
             - name: DOCKERFILE
               value: "Dockerfile"
           workspaces:
             - name: source
               workspace: shared-workspace

         - name: deploy-app
           runAfter:
             - build-image
           workspaces:
             - name: source
               workspace: shared-workspace
           taskSpec:
             workspaces:
               - name: source
             steps:
               - name: apply-and-verify
                 image: quay.io/openshift/origin-cli:latest
                 script: |
                   #!/usr/bin/env bash
                   set -e
                   cd $(workspaces.source.path)
                   oc apply -f kubernetes/deployment.yaml -n my-app-dev
                   oc set image deployment/my-app-simple my-app-simple=image-registry.openshift-image-registry.svc:5000/my-app-dev/my-app-simple:$(params.revision) -n my-app-dev
                   oc rollout status deployment/my-app-simple -n my-app-dev --timeout=300s


5. Comandos Clave de Operación y Monitoreo
--------------------------------------------------------------------------------

* **Sincronización y Push a GitLab:**
  
  .. code-block:: bash

     cd ~/my-app-simple
     git add .
     git commit -m "feat: complete CI/CD pipeline configuration"
     git push origin develop

* **Monitoreo de PipelineRuns en OpenShift:**
  
  .. code-block:: bash

     oc get pipelineruns -n my-app-dev -w

* **Inspección de Pods y Logs ante incidencias:**
  
  .. code-block:: bash

     oc get pods -n my-app-dev
     oc logs -n my-app-dev <nombre-del-pod-con-error> --tail=100
